# Pile ML : deux jeux de contraintes mutuellement exclusifs.
#
# macOS Intel (x86_64) : PyTorch ne publie plus de wheel x86_64 au-delà de
# 2.2.2, ce qui plafonne toute la pile. Sans ces bornes, pip installe
# transformers 5.x (qui exige torch >= 2.5), désactive torch en silence, puis
# échoue sur « NameError: name 'nn' is not defined ». numpy doit rester en 1.x :
# torch 2.2.2 est compilé contre l'ABI numpy 1.
#
# ⚠️ Mac Intel : PYTHON 3.12 MAXIMUM. Les wheels macOS x86_64 de torch 2.2.2
# (cp38-cp312) et de numpy 1.26.4 (cp39-cp312) ne couvrent pas Python 3.13+.
# Sous 3.13, pip ne trouve rien d'installable et tente une compilation qui
# echoue. launch.sh verifie ce point et s'arrete avec un message explicite.
#
# sentence-transformers 5.6 (GHSA-jhr6-gm9c-rqjv) tourne avec cette pile :
# essayé le 10/11/2026 avec torch 2.2.2, numpy 1.26.4 et transformers 4.57.6
# (sous Windows, Python 3.11 : mêmes versions, autre OS), mêmes vecteurs et
# mêmes scores du reranker qu'avec la pile récente. Risque résiduel propre au
# Mac Intel : torch 2.2.2 garde ses failles connues (dont torch.load, corrigée
# en 2.6) faute de wheel x86_64 plus récente.
#
# Partout ailleurs (Windows, Linux, Apple Silicon) : bornes hautes majeures
# calées sur la pile validée en local (torch 2.15, transformers 4.57,
# sentence-transformers 5.7, numpy 2.5) pour qu'une installation neuve ne
# ramasse pas « la dernière version de tout ».
# ------------------------------------------------------------------------
